# REPORT-masters.md — Миграция «Мастера» и форматы занятий

Документ описывает всё реализованное в рамках этой миграции и фиксирует вопросы, требующие подтверждения от Лизы.

## Что сделано

### Схема БД (prisma/schema.prisma)

- Добавлен enum `ServiceFormat`: `group`, `individual`, `course_group`, `course_individual`, `subscription`, `seasonal`
- Добавлен enum `MasterExceptionKind`: `closed`, `extra`
- `Service` получил поле `format ServiceFormat @default(group)` и связь с `PriceTier[]`
- Новые модели: `Master`, `ServiceMaster` (M2M), `PriceTier`, `MasterAvailabilityRule`, `MasterException`
- `Slot` получил `masterId String?` — групповые слоты имеют `null`, индивидуальные указывают на мастера
- Уникальность слотов: `@@unique([serviceId, startsAt, masterId])`. PostgreSQL трактует NULL != NULL, поэтому дубликаты групповых слотов (masterId=null) дополнительно защищены на уровне приложения
- Добавлены категории: `glass` (Витраж и стекло, sortOrder 6), `coworking` (Коворкинг керамики, sortOrder 7)

### Доменный слой (src/lib/domain/slots.ts)

- `generateSlots` — без изменений логики, теперь явно ставит `masterId: null`
- `generateMasterSlots` — новая функция: берёт `MasterAvailabilityRule` + `MasterException` мастера, генерирует слоты на 30 дней с учётом закрытых дней (kind=closed) и дополнительных часов (kind=extra)

### Админ-панель

- Раздел «Команда» в боковой навигации (доступен всем 3 ролям: owner, admin, tech)
- `/admin/masters` — список мастеров с аватаром, статусом, тегами услуг
- `/admin/masters/new` и `/admin/masters/[id]` — редактор:
  - Основные данные: имя, фото (URL), описание, флаг «показывать на сайте»
  - Услуги: чекбоксы для привязки мастера к занятиям
  - Шаблон недели: 7-колоночная сетка, добавление правил (день + время с/до), удаление
  - 30-дневный календарь: клик = закрыть/открыть день (MasterException kind=closed)
  - Кнопки: «Скрыть/Показать» (все роли) и «Удалить из базы» (owner only, с двойным подтверждением)

## Технические решения (архив)

- NULL в уникальном индексе: PostgreSQL не считает NULL = NULL, поэтому два групповых слота (masterId=null) на одно время дедуплицируются на уровне приложения
- Удаление мастера двухуровневое: `active=false` (скрыть) доступно всем ролям; физическое удаление из БД только owner, проверка на сервере через `getServerSession`
- Абонемент не создаёт Slot и Booking — только AuditLog, чтобы не захламлять расписание фиктивными слотами
