## Что делать, если пошло не так

### Заказчица поменяла A-запись, а сайт не открывается

1. Проверь `dig princulissart.ru @1.1.1.1 +short`. Если старый IP —
   ещё не распространилось, жди.
2. Если новый IP, но `curl https://princulissart.ru/` не отвечает — смотри
   логи Caddy: `docker compose logs caddy --tail 50`. Обычно = не выдал
   сертификат из-за DNS или закрытого порта.
3. `ufw status` — должно быть 80/443 открыты. Если нет — открой.

### Caddy не выпустил сертификат

Обычно = DNS не распространился до внешних резолверов Let's Encrypt.
Подожди ещё 5-10 минут. Если больше 30 — проверь `dig` от Cloudflare и
Google DNS одновременно.

### Заявка отправилась, в amoCRM не пришла

1. Проверь `amoStatus` в базе. Если `pending` — жди, cron повторит через
   5 минут.
2. Если `failed` — читай `lastError`: `SELECT id, lastError FROM Request
   WHERE amoStatus='failed' ORDER BY createdAt DESC LIMIT 3;`
3. Обычные причины: неверный `AMO_ACCESS_TOKEN`, неверный `AMO_SUBDOMAIN`,
   протух токен. Проверь `.env`.

### В Telegram не пришло уведомление

1. `docker compose logs app --tail 100 | grep -i telegram`
2. Обычные причины: неверный `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`.
3. `TELEGRAM_API_BASE` в `.env` — если пусто, идёт напрямую к
   api.telegram.org, что может блокироваться на РФ-хостинге. Если есть
   Cloudflare Worker для теста — используй его же для боевого.
