## Правила работы, обязательные

1. **Читай `CLAUDE.md` в корне проекта первым делом.** Там правила проекта,
   их нарушать нельзя.

3. Каждый шаг, который меняет прод, начинается с бэкапа и точки возврата.
4. Если хук отклоняет коммит (сырой hex, длинные тире, что-то ещё) — чинить
   по-настоящему, не обходить.
5. Никаких «git checkout --» без git status и осознанного разбора. Ничего
   не терять из работы студии.
6. Все команды на боевом сервере — через SSH, никаких прямых правок в
   Docker-контейнерах, если это не восстановление.
7. Отчитывайся коротко: сделано / доказательство / следующий шаг. Без
   вступлений.

## План дня, по часам

Ориентир — начало сейчас. Активной работы около 5 часов + буферы.

### Часть 1. Наполнение (2-4 часа)

1. Забрать Excel-файл у пользователя.
2. Распарсить нужные листы (расписание, часы, открытые дни, мастера —
   доп. поля, занятия, потоки курсов, праздники, категории, сотрудничество,
   бонусы, отзывы, события, работы, товары, статья, тексты главной,
   вопросы). Смотри готовый парсер XLSX в `/tmp/masters/parse.py` на
   тестовом окружении, если ещё жив; иначе напиши свой.
3. Для каждого раздела написать скрипт импорта на CJS в `scratchpad/`,
   загрузить в контейнер боевого сервера через `docker compose cp`,
   выполнить `docker compose exec -T app node /tmp/...`.
4. **После КАЖДОГО импорта:** сбросить кэш чтения
   (`rm -rf /app/.next/cache` в контейнере) + `docker compose restart app`.
   Иначе изменения не появятся на страницах.
5. Приоритет: сначала расписание+часы+фото мастеров+праздников (без них
   сайт выглядит нерабочим), потом остальное.
6. Пропущенные фото (у мастеров без фото, у праздников): попросить у
   студии либо оставить пустыми — не выдумывать.

### Часть 2. Уборка демо (15 минут)

Убрать всё помеченное «(демо)». Ищи в базе `LIKE '%(демо)%'` и
`path='/medallion.jpg'`:
- ScheduleSlot с занятием «Гончарный круг» суббота 12:00;
- FreeDay 20 сентября;
- Review Марии (демо);
- Event «Маркет керамики (демо)»;
- BonusLevel «Постоянный гость (демо)» и его BonusPerk;
- Work «Чашка "Утро" (демо)»;
- ShopItem «Сертификат 3000 ₽ (демо)», «Глина белая 10 кг (демо)»;
- Media с path='/medallion.jpg' (это моя эмблема, ставилась как заглушка);
- Article опубликованный черновик вернуть в статус draft, если он не
  является реальной статьёй.

### Часть 3. Настройка боевого окружения (30 минут)

1. Правка `/root/app/.env` на боевом:
   - `NEXT_PUBLIC_NOINDEX=` (пусто, снять запрет индексации);
   - `NEXT_PUBLIC_SITE_URL=https://princulissart.ru`;
   - `CADDYFILE=` (пусто, взять боевой Caddyfile, не Caddyfile.test);
   - `AMO_ACCESS_TOKEN=<новый от студии>`;
   - `TELEGRAM_BOT_TOKEN=<от студии>`, `TELEGRAM_CHAT_ID=<от студии>`;
   - Переменные `TEST_*` можно оставить, они не мешают.
2. Проверить Caddyfile (боевой) содержит `princulissart.ru, www.princulissart.ru`.
3. Внести почту для обращений в политику (заменить `[указать]` в
   `app/(site)/politika/page.tsx` и в `docs/politika-personalnyh-dannyh.md`).

### Часть 4. Заглушка и первая сборка (30 минут)

1. `sh scripts/maintenance-on.sh` — включить страницу «обновляем сайт».
2. Убедиться, что заглушка сама отвечает: `curl -I` на любой URL, должен
   быть 503 + `Retry-After`.
3. Пересобрать: `sh scripts/deploy.sh`. Дождаться «Готово».
4. Пока сборка идёт, окончательно свериться со студией по токенам.

### Часть 5. Переключение домена (30 минут, из них ожидание 5-10 минут)

1. **Попросить студию** переключить A-записи `princulissart.ru` и `www` на
   `159.194.234.214`.
2. Ждать распространения DNS (`dig princulissart.ru @1.1.1.1` +12.15).
   При TTL 300 — около 5 минут. При обычном TTL — до часа.
3. Как только `dig` показывает новый IP: первый `curl https://princulissart.ru/`
   на сервере запустит выпуск сертификата Let's Encrypt (30-60 секунд).
   Проверить в логах Caddy: `docker compose logs caddy --tail 50`.

### Часть 6. Проверка на боевом адресе (60 минут)

Полный release-check:

- Все страницы открываются, консоль чистая: `/`, `/o-nas`, `/raspisanie`,
  `/zanyatiya/...` (3 разных), `/kupit`, `/kupit/...` (2 разных),
  `/komanda`, `/komanda/...` (2 разных), `/otprazdnovat`, `/otprazdnovat/...`,
  `/sotrudnichestvo`, `/bonusy`, `/blog`, `/blog/...`, `/voprosy`,
  `/kontakty`, `/politika`, `/zapis`, `/sitemap.xml`, `/robots.txt`, 404.
- **robots.txt открыт для индексации** (не `Disallow: /`).
- **Нет заголовка X-Robots-Tag: noindex**.
- Sitemap содержит все реальные адреса, не 5.
- Ровно один H1 на каждой странице.
- 320px без горизонтальной прокрутки (проверить на iPhone).
- Заголовки безопасности на месте (CSP, HSTS, X-Content-Type-Options).
- Сертификат Let's Encrypt валиден.

**Контрольные заявки — по одной с каждой формы:**
- `/zapis` (booking) — приходит в amoCRM, в Telegram.
- `/raspisanie` индивидуальное время (free_time).
- `/otprazdnovat/<slug>` (celebration).
- `/sotrudnichestvo/<slug>` (partnership).
- `/kupit/<slug>` (purchase).
- `/kupit/<slug>` из категории с requestKind=booking (курс).

**Заявки помечать в комментарии** `КОНТРОЛЬНАЯ 2026-09-XX` — потом всё
удалить одним запросом.

### Часть 7. Открытие сайта (15 минут)

1. Финальная проверка: если все 6 форм успешно отправляют, все страницы
   200, консоль чистая — снимаем заглушку.
2. `sh scripts/maintenance-off.sh`.
3. `curl -I https://princulissart.ru/` — должен быть 200, без 503.
4. Проверить главную и заявку ещё раз.
5. **Удалить контрольные заявки** из базы:
   `DELETE FROM Request WHERE comment LIKE '%КОНТРОЛЬНАЯ%';`
6. В amoCRM пометить контрольные сделки на удаление (через API нельзя,
   попросить студию удалить вручную по фильтру «КОНТРОЛЬНАЯ»).

### Часть 8. Пост-переезд (30 минут)

1. Проверить cron: `crontab -l`. Должен быть: бэкап 04:00, повтор заявок
   каждые 5 мин, чистка медиа, чистка кэша.
2. Запустить бэкап руками: `docker compose exec -T app sh /app/scripts/backup.sh`.
   Убедиться что появился файл в `/app/backups/`.
3. Отдать sitemap в Яндекс.Вебмастер:
   `https://princulissart.ru/sitemap.xml`. Ссылку добавить в Search Console.
4. Обновить `STATE.md`: переезд завершён, дата, коммит.
5. Коммит + пуш.

### Часть 9. Первые 24 часа

- Старый тестовый сервер `80.78.253.177` **не выключать**.
- Через 24 часа: попросить студию **вернуть TTL** домена к обычному
  (3600). После этого старый сервер можно выключать.

## Правила отката

**До момента снятия заглушки** (Часть 7 шаг 2) — откат прост: попросить
студию вернуть A-записи домена на старый IP. Старый сервер живой,
принимает трафик.

**После снятия заглушки** — откат сложнее: гости уже видели новый сайт,
могли отправить заявки. Восстанавливать из бэкапа только по прямой
команде студии.

## Критические моменты, где нужно подтверждение студии

1. **Перед переключением A-записи** (Часть 5.1): подтвердить, что готовы к
   переезду и что backup у нас есть.
2. **Перед снятием заглушки** (Часть 7.2): подтвердить, что release-check
   пройден и всё выглядит нормально.
3. **Перед удалением контрольных заявок** (Часть 7.5): подтвердить, что
   заявки дошли до amoCRM и в Telegram.

## Если что-то пошло не так

- Сборка упала: не паникуй, откат: `sh scripts/rollback.sh`.
- Caddy не выдал сертификат: `docker compose logs caddy`, обычно = DNS ещё
  не распространился или порт 80 закрыт (`ufw status`).
- Форма записи не отправляет: проверь `.env` (SESSION_SECRET,
  ENCRYPTION_KEY, CRON_SECRET), логи `docker compose logs app`.
- Заявка не идёт в amoCRM: смотри `AMO_ACCESS_TOKEN`, `AMO_SUBDOMAIN`.
- Заявка не идёт в Telegram: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`,
  `TELEGRAM_API_BASE` (если есть релей).

Всё, начинай с чтения `CLAUDE.md` и уточнения у студии всех токенов.
Никакой отсебятины на боевом сервере.
