КРИТИЧНЫЙ РАБОЧИЙ ПРОЦЕСС (не наступи на грабли):
- Смотреть сайт ТОЛЬКО через `node .next/standalone/server.js`, НЕ через `npm start`. В next.config.ts включён output:"standalone" ради Docker, а next start с ним не поддерживается: ломается раздача статики и /_next/image (свежее фото даёт 404, часть страниц падает 500 на чанках). `npm run build` сам синхронизирует public/ и .next/static в .next/standalone (scripts/sync-standalone-assets.ts). Дев-сервер поднимать только через preview_start, не Bash; никогда build при запущенном dev.
- Тесты идут на ДЕМО-сиде: перед `npm run check` делай `npm run seed` (e2e хардкодит демо-занятие «Гончарный круг для начинающих»). ПОСЛЕ проверки верни реальный контент: `npm run import:content -- "C:\Users\Mi\Downloads\Фото-20260820T092520Z-1-001\Фото"`, затем `npm run media:prune -- --yes` (импорт заводит фото заново, старые остаются мусором).
- Перед рискованными операциями с данными: `npm run data:snapshot` (снимок базы и фото в backups/, разворачивается `-- restore <путь>`). Проверено на практике.
- unstable_cache сериализует результат в JSON: Date приезжает СТРОКОЙ. Всё, что читает даты через cachedRead, обязано оживлять их `new Date(...)` после кэша — иначе 500 на `.getTime()` (так было с Event.date и CourseRun.startDate). Сборка это не ловит: динамические страницы она не рендерит, ловится только в браузере.
- unstable_cache переживает правку БД и чистку .next/cache на Windows: чтобы увидеть изменения после импорта или прямой правки базы, сноси весь `.next` и пересобирай.
- Панель за логином, вручную не тестируется (ввод пароля запрещён правилом безопасности) — проверяй типами/сборкой + e2e (он логинится через SEED_OWNER_* из env). Сейчас 7 e2e и 107 юнит-тестов, все зелёные.
- Превью-панель браузера иногда сворачивается (скриншот падает «pane not displayed») — фронти вкладку через tabs_select.

ПРАВИЛА КОДА (ключевое):
- zod v4. any запрещён. Серверная валидация обязательна. Секреты только из env.
- Цвет только var(--*) через color-mix; сырой hex — лишь в токен-файлах и внутри gradient()/shadow. Перед любой правкой вёрстки — таблица расхождений с макетом 4-2-2 на 320/390/1440.
- Один H1 на страницу, без длинного тире, тексты на русском. Новых зависимостей не добавлять без спроса (для Markdown уже есть marked и dompurify в зависимостях, sanitize обязателен).
- Роли проверяются на сервере в каждом действии (обёртка panelAction: роль → zod → транзакция → журнал → сброс кэша). Карта сброса — ARCHITECTURE раздел 3.
- Поле, которое нечем заполнить, НЕ выводится (пустая цена, пустой блок): выдуманные значения дают санкции поиска. Пустой раздел показывает честное состояние, а не подсказку про несуществующие фильтры.
