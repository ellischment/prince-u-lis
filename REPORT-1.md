# Отчёт по этапу 1 — Домен записи

## Что сделано

### Prisma-схема (полная замена)

Старая схема из этапа 0 заменена новой доменной моделью с 13 таблицами:

- **Category / Service / ServiceCategory** — каталог услуг с явной M2M-таблицей (вместо неявного `connect`)
- **ServiceProgramItem / ServiceIncludeItem** — программа и состав включены как дочерние таблицы, не JSON-массивы: можно редактировать поштучно
- **ScheduleRule** — расписание теперь хранит `weekday: Int` (0=Вс … 6=Сб, как `Date.getDay()`) вместо enum `DayOfWeek`
- **Slot** — поле `startsAt: DateTime` вместо двух строк `date + time`; уникальный индекс `[serviceId, startsAt]`
- **Client** — выделен из Booking; телефон уникален; хранит `visitsCount` (только статус `done`)
- **Consent** — отдельная таблица для 152-ФЗ: версия документа, IP, время каждого согласия
- **Booking** — расширенный enum статуса: `new | confirmed | done | cancelled | no_show`
- **Promo / PromoCode / User / ContentText / AuditLog** — без изменений по смыслу, поля приведены к camelCase

### Доменные сервисы (`src/lib/domain/`)

Написаны 5 функций:

| Функция            | Что делает                                                                                                                                              |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `generateSlots`    | Чистая функция: из правил расписания и списка сервисов строит `SlotCandidate[]` на N дней вперёд без обращения к БД                                     |
| `remaining`        | Чистая функция: `max(0, capacity – bookedCount)`                                                                                                        |
| `bookSlot`         | Транзакция: upsert Client → Consent → Booking. Защита от гонки: читает активные записи внутри той же транзакции и бросает `SlotFullError` если мест нет |
| `everySeventhFree` | Проверяет `visitsCount % 7 === 0 && visitsCount > 0` — каждые 7 выполненных занятий бесплатно                                                           |
| `cancelBooking`    | Транзакция: меняет статус на `cancelled`; если статус был `done` — декрементирует `visitsCount`                                                         |

## Что отложено

- Миграция БД (`prisma migrate dev`) — требует запущенного Docker. Схема готова, при старте Docker выполняется одной командой
- API-маршруты (`/api/slots`, `/api/bookings`) — этап 2
- Публичный сайт — этап 2
- Перевод `visitsCount` в `done` при подтверждении записи — действие в admin-панели, этап 3

## Принятые решения

- **`weekday: Int`** — никакого преобразования между `Date.getDay()` и enum; число приходит из БД и сразу используется
- **`startsAt: DateTime`** — один индекс вместо составного `(date, time)`; часовой пояс обрабатывается на уровне приложения (UTC в БД, Moscow-offset на клиенте)
- **Чистые функции без БД** — `generateSlots` и `remaining` тестируются без мока Prisma; быстро и просто
- **Мок транзакции в тестах** — `$transaction` мокируется как `fn => fn(tx)`, где `tx` — объект с нужными vi.fn(). Реальная BD не нужна для unit-тестов
- **Отдельные таблицы для program/includes** — вместо `String[]` (Prisma не поддерживает массивы в PostgreSQL напрямую без `@db.Array`): даёт сортировку, редактирование поштучно и возможность локализации
