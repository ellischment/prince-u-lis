# FEATURES. Логика каждой функции

Разбор каждой функции по одной схеме: что видит гость, как работает, крайние случаи, что настраивается в панели, как проверить. Читается вместе со `SPEC.md` и `ARCHITECTURE.md`.

# ЧАСТЬ 1. САЙТ

## 1.1. Шапка со сворачиванием

**Что видит гость.** Плашка сверху с логотипом, меню, телефоном и кнопкой записи. При прокрутке она остаётся, но становится ниже, меню исчезает.

**Логика.**
- Слушатель прокрутки с ограничением частоты через `requestAnimationFrame`
- Порог 140 пикселей. Больше порога добавляется состояние `slim`, меньше снимается
- В состоянии `slim`: высота 72 → 56, меню скрыто, показана кнопка меню
- Телефон виден всегда. Ширина меньше 700: превращается в круглую кнопку со значком

**Крайние случаи.**
- Ширина 320: логотип уменьшается, отступы сжимаются. Проверено, что логотип, телефон, кнопка и бургер помещаются
- Прокрутка ровно на пороге: гистерезис не нужен, состояние меняется по одному значению, дребезга нет из-за ограничения частоты

**Проверка.** Прокрутить на 600, шапка на месте и сжата. Вернуться наверх, меню вернулось. Сузить до 320, ничего не вылезает.

## 1.2. Анкета «Чем займёмся»

**Что видит гость.** Шесть кнопок с поводом визита. После нажатия каталог ниже показывает подходящее, заголовок меняется, появляется подсказка про формат праздника.

**Логика.**
1. У каждого занятия есть теги задач (`LessonTaskTag`)
2. Нажатие кнопки записывает выбранную задачу в состояние страницы
3. Каталог фильтруется: остаются занятия, у которых есть этот тег
4. Заголовок каталога меняется на «Вот что вам подойдёт», появляется кнопка «Показать все занятия»
5. Под кнопками появляется подсказка с переходом: для «вдвоём» на формат «Свидание», для «подарок» на карточку сертификата, для «уже умею» на коворкинг
6. Ряд фильтров направлений становится приглушённым: активен подбор по задаче
7. Повторное нажатие той же кнопки снимает выбор

**Крайние случаи.**
- Под задачу не нашлось ни одного занятия: показывается подсказка снять фильтр, а не пустой экран
- Одно занятие может иметь несколько тегов и попадать в разные задачи
- Выбор направления вручную сбрасывает выбор задачи

**В панели.** Раздел «Расписание», блок анкеты: состав кнопок, название каждой, какие занятия и форматы подбираются, показ кнопки.

**Проверка.** Нажать все шесть кнопок по очереди. В каждой подборка не пустая или есть подсказка. Заголовок меняется. Сброс работает.

## 1.3. Каталог занятий: два ряда фильтров

**Что видит гость.** Два ряда кнопок: направление и формат. Работают вместе.

**Логика.**
```
список = все занятия с visible = true
если выбрана задача анкеты  -> оставить занятия с этим тегом
иначе если выбрано направление и оно не «все» -> оставить занятия этого направления
если выбран формат и он не «любой» -> дополнительно оставить занятия этого формата
```

**Особые значения.**
- «Коворкинг» в ряду направлений это не занятие, а услуга: вместо списка показывается объяснение и кнопка перехода к тарифам
- «События» выделены цветом: нажатие прокручивает к блоку событий, фильтр не применяется
- «Курсы» в ряду направлений отбирает занятия с форматом «курс»

**Крайние случаи.**
- Пустое сочетание, например «детям» и «индивидуальные»: подсказка снять один фильтр
- Категория без занятий не показывается в ряду вообще

**В панели.** Состав, названия, порядок и показ обоих рядов. Привязка занятия к направлению и формату.

**Проверка.** Перебрать сочетания, включая заведомо пустое. Проверить коворкинг и события.

## 1.4. Галерея занятия и просмотр на весь экран

**Что видит гость.** Одно крупное изображение и четыре мелких. На последнем метка «ещё N». Нажатие открывает просмотр во весь экран.

**Логика.**
- Список медиа занятия по порядку `sort`
- Первое идёт крупным, следующие четыре мелкими
- Если медиа больше пяти, на пятом показывается «ещё N», где N это остаток
- Нажатие открывает просмотрщик с индексом нажатого кадра
- Просмотрщик: стрелки влево и вправо, клавиши стрелок, миниатюры внизу, закрытие по Esc и по нажатию мимо кадра
- Прокрутка страницы блокируется, пока просмотрщик открыт
- Видео открывается тем же просмотрщиком, внутри встроенный плеер площадки

**Крайние случаи.**
- Одно медиа: мелких нет, просмотрщик всё равно открывается
- Ноль медиа: место занимает заглушка, просмотрщик не открывается
- Видео первым в списке: крупным идёт оно, со значком воспроизведения

**В панели.** Загрузка изображений, порядок перетаскиванием, подключение видео ссылкой, удаление.

**Проверка.** Открыть просмотр, пролистать стрелками и клавишами, закрыть по Esc. Убедиться, что страница не прокручивается под просмотрщиком.

## 1.5. Расписание: левый столбец

**Что видит гость.** Семь дней недели без чисел. Развёрнут сегодняшний. Рядом с днём ключевые слова.

**Логика.**
1. Дни всегда в порядке от понедельника до воскресенья
2. Текущий день вычисляется на сервере по московскому времени: `(getDay() + 6) % 7` даёт индекс, где 0 это понедельник
3. Занятия дня берутся из `ScheduleSlot` по `weekday`
4. Ключевые слова: направления занятий этого дня, без повторов, через разделитель
5. Внутри дня строка занятия: название ссылкой на страницу, время, кнопка записи
6. Нажатие на заголовок дня разворачивает и сворачивает

**Крайние случаи.**
- В дне нет занятий: показывается предложение прийти индивидуально со ссылкой на правый столбец
- Занятие скрыто в панели: пропадает из расписания, слот остаётся
- Занятие удалено: слот подсвечивается в панели как битый, на сайте не показывается

**В панели.** Сетка недели: добавление, изменение, удаление строк. Часы работы по дням.

**Проверка.** Открыть сайт, убедиться, что развёрнут именно сегодняшний день. Нажать на название занятия, открылась его страница. Нажать «Записаться», занятие и время подставились.

## 1.6. Расписание: правый столбец, индивидуальное время

**Что видит гость.** Календарь месяца, открытые дни подсвечены. После выбора дня появляется время. Ниже прямая фраза, что это заявка, а не бронь.

**Логика.**
1. Открытые дни берутся из `FreeDay` с `visible = true`
2. Прошедшие даты не подсвечиваются и не выбираются
3. После выбора дня показывается его список времени плюс кнопка «любое время»
4. Отдельная строка «нужно другое время» раскрывает поле произвольного ввода
5. Отправка требует выбранный день и либо время из списка, либо «любое время», либо произвольное время
6. После отправки на месте блока появляется подтверждение с тем, что выбрал гость
7. Время не помечается занятым нигде: заявка не блокирует слот

**Крайние случаи.**
- Выбрано время из списка и одновременно введено произвольное: произвольное имеет приоритет, это видно в подтверждении
- Все дни месяца закрыты: календарь показывается, подсказка предлагает написать в мессенджер
- Гость выбрал день, потом переключил месяц: выбор сбрасывается

**В панели.** Открытые даты и их время, копирование набора времени на несколько дат.

**Проверка.** Выбрать день без времени, отправка не проходит с понятным сообщением. Выбрать «любое время», проходит.

## 1.7. Форма записи в три шага

**Что видит гость.** Три пронумерованных блока: на что, кто, как связаться.

**Логика по шагам.**

*Шаг 1. Выбор занятия.* Свой раскрывающийся список, не системный. Сгруппирован по направлениям, в строке название и цена. Первым пунктом «пока выбираю, подскажите». После выбора под списком появляется сводка: длительность, уровень, цена и время, если гость пришёл из расписания. В сводке две ссылки: открыть страницу занятия и выбрать другое.

*Шаг 2. Кто вы.* Имя и телефон, оба обязательны. Телефон приводится к единому формату при вводе.

*Шаг 3. Как связаться.* Пять вариантов: звонок по умолчанию, Telegram, WhatsApp, MAX, SMS. Поле комментария. Галочка согласия.

**Подстановка контекста.**
- Переход со страницы занятия: занятие подставлено, показана пометка
- Переход из строки расписания: подставлены занятие и время
- Ручная смена занятия в списке сбрасывает подставленное время, чтобы не осталось чужого
- Переход из каталога товара: тип заявки «покупка», в комментарий подставлено название товара

**Валидация.** Серверная обязательна. Ошибки подсвечивают поля, курсор ставится в первое незаполненное, введённое не теряется. Согласие без галочки блокирует отправку.

**После отправки.** Форма заменяется экраном подтверждения с названием занятия и кнопкой отправить ещё одну. Повторное открытие формы очищает поля.

**Крайние случаи.**
- Двойное нажатие кнопки: кнопка блокируется на время отправки
- Отправка при недоступной сети: сообщение с предложением позвонить, введённое сохраняется
- Занятие скрыли в панели, пока гость заполнял форму: заявка принимается, в комментарий добавляется пометка

**Проверка.** Пройти форму с клавиатуры без мыши. Отправить без согласия, без имени, с коротким телефоном.

## 1.8. Каталог «Купить»: три вкладки

**Что видит гость.** Вкладки Работы, Сертификаты и курсы, Керамистам.

**Логика вкладки «Работы».**
- Два ряда фильтров: автор (все, Елисаветы, мастеров) и материал (керамика, живопись, витраж)
- Фильтры работают вместе, как в каталоге занятий
- Сетка фотографий без подписей, порциями по восемь, кнопка «показать ещё»
- Нажатие открывает страницу работы: изображение, описание, цена, кнопка «Купить»
- Кнопка «Купить» отправляет заявку с типом «покупка», ссылок на занятия на странице нет

**Логика вкладки «Сертификаты и курсы».** Карточки с описанием, ценой и переходом на страницу условий. Здесь же блок коворкинга с тремя тарифами, к нему ведёт пункт меню и якорь.

**Логика вкладки «Керамистам».** Карточки того же вида. Ряд подкатегорий второго уровня: глина и массы, глазури и ангобы, инструмент, обжиг. Выбор подкатегории фильтрует список.

**Тип отображения.** Берётся из поля `display` категории первого уровня: `showcase` даёт сетку без подписей, `cards` даёт карточки. Подкатегории наследуют.

**Крайние случаи.**
- Пустая подкатегория: подсказка, что здесь пока пусто
- Категория скрыта: вкладка не показывается
- Товар без изображения: заглушка с первой буквой названия

**Проверка.** Переключить все три вкладки, применить фильтры, открыть товар, отправить заявку на покупку.

## 1.8a. Курсы

**Что видит гость.** Отдельный пункт меню и витрину курсов. У карточки название, число встреч, цена за курс и ближайшая дата старта.

**Логика витрины.**
```
курсы = занятия с форматом course и visible = true
для каждого берётся ближайший поток: CourseRun с startDate >= сегодня, по возрастанию, первый
если потоков нет -> карточка показывается с пометкой «набор скоро откроется»
```

**Страница курса.** Всё то же, что на странице занятия, плюс блок «Ближайшие потоки»: список из двух-трёх ближайших, у каждого дата старта, число встреч, когда проходят, кнопка записи.

**Запись на курс.** Кнопка потока подставляет в форму название курса и дату старта. В комментарий заявки добавляется поток, чтобы администратор не переспрашивал.

**Если потоков нет.** Кнопка «Сообщить о наборе». Заявка уходит с пометкой в комментарии, тип обычный.

**Крайние случаи.**
- Поток стартовал вчера: автоматически скрывается, не показывается как ближайший
- Все потоки прошли: карточка остаётся с пометкой про набор, кнопка меняется
- Курс скрыт: пропадает и из витрины, и из каталога занятий

**В панели.** Раздел «Занятия»: у занятия с форматом «курс» появляется блок потоков. Добавить поток: дата старта, число встреч, когда проходят, примечание, показ.

**Проверка.** Открыть `/kursy`, увидеть карточки с датами. Открыть курс, записаться на поток, убедиться что дата попала в заявку.

## 1.9. Порции и постраничная навигация

**Что видит гость.** Кнопку «показать ещё» под списками.

**Логика.** Двойная: кнопка для человека и адреса страниц для поисковых роботов.

- Список отдаётся страницами: `/blog`, `/blog/2` и далее. Каждая страница рендерится на сервере
- Кнопка «показать ещё» догружает следующую порцию без перезагрузки, но её наличие не отменяет адреса
- В разметке присутствуют ссылки на следующую и предыдущую страницы
- Размер порции: девять для работ, шесть для статей, двенадцать для событий

**Почему так.** Кнопка, сделанная только на JavaScript, отдаёт роботу первую порцию и ничего больше. Остальное для поиска не существует.

**Проверка.** Отключить JavaScript в браузере и пройти по списку через адреса. Все элементы доступны.

## 1.10. Карусели с управлением

**Что видит гость.** Карусель мастеров, событий, медиа праздника. По краям стрелки.

**Логика.**
- Прокрутка колесом и пальцем работает всегда
- Стрелки показываются только если содержимое шире контейнера
- Стрелка гасится, когда карусель дошла до края
- Пересчёт на изменении размера окна и на прокрутке карусели
- Шаг прокрутки равен ширине карточки плюс отступ

**Крайние случаи.**
- Элементов мало, всё помещается: стрелок нет вообще
- Один элемент: карусель ведёт себя как обычный блок

**Проверка.** На широком экране стрелок нет, на узком есть и работают, на краю гаснут.

## 1.11. Отзывы

**Что видит гость.** Три отзыва: видео, фото и текст, у каждого короткое описание.

**Логика.**
- Показываются только отзывы со статусом «опубликован»
- Видео встраивается плеером площадки по ссылке
- Фото показывается через просмотрщик
- Текстовый отзыв показывается цитатой

**Ограничение.** Отзыв с фото или видео не может получить статус «опубликован», если не отмечено получение письменного согласия. Проверка на сервере, а не только в интерфейсе.

**Проверка.** Попробовать опубликовать видеоотзыв без отметки согласия через панель и через прямое обращение к действию. Оба раза отказ.

## 1.12. События

**Что видит гость.** Карусель: два ближайших будущих и одно последнее прошедшее. Подписи «Ждём вас» и «Как это было».

**Логика.**
```
будущие = события с датой >= сегодня, по возрастанию даты, взять 2
прошедшие = события с датой < сегодня, по убыванию даты, взять 1
порядок = будущие, затем прошедшее
```
Первое будущее выделяется рамкой как ближайшее.

**Автоматика.** Ежедневная фоновая задача переводит события с прошедшей датой в архив. Это не удаление: событие остаётся с фотоотчётом.

**Крайние случаи.**
- Нет будущих событий: показываются два последних прошедших
- Нет событий вообще: блок не показывается

## 1.13. Полоса работ на главной

**Что видит гость.** Ленту из шести карточек с подписью: название и короткое описание. Одна карточка с видео.

**Логика.**
- Берутся пять работ без видео и одна с видео, если такая есть

- Карточка с видео открывает просмотрщик

## 1.14. Оформление: сезоны, гирлянда, звёзды

**Сезоны.** Три режима из настройки `season`: `flags`, `winter`, `off`. Флажки показывают гирлянды, зима добавляет снег, выключенный режим убирает украшения. Переключается в панели, применяется сразу.

**Гирлянда: итоговая композиция.** Подобрана визуально и зафиксирована в прототипе. Три нити: первая слева уходит под шапку, вторая начинается под шапкой и глубоко провисает к правому краю, третья идёт ниже за содержимым. Первые две поверх текста и медальона, третья за ними. Точные числа в прототипе, в задании не фиксируются: это оформление, а не требование.

**Гирлянда: иерархия слоёв.** У каждой нити настраивается слой: за содержимым или поверх него. Нить поверх заходит на заголовок и иллюстрацию, и это осознанное решение, а не случайность: гирлянда становится частью композиции, а не полосой сверху.

Условия, при которых слой поверх допустим:
- У флажков включена тень: без неё ткань сливается с тем, что под ней
- Текст под гирляндой остаётся читаемым: проверяется на контраст, а не на глаз
- Гирлянда не перекрывает кнопки и ссылки: слой не перехватывает нажатия, но визуально закрытая кнопка это потерянная запись
- На узком экране слой поверх используется осторожнее: там текста больше на единицу площади

**Гирлянда: утверждённая композиция.** Подобрана визуально и зафиксирована. В договорном задании эти числа не приводятся: там только требования, композиция остаётся вопросом оформления.

```js
// layer:1 означает слой поверх заголовка и иллюстрации
BUNT1 = {seg:[0,0.34],  yL:71,  yR:-1,  sag:65,  asym:0, step:52, fw:49, fh:43,
         tilt:92,  jitter:35, fold:1, cord:15, shift:0, layer:1, opacity:93, shadow:45,  speed:100}
BUNT2 = {seg:[0.39,1], yL:-55, yR:200, sag:142, asym:5, step:53, fw:45, fh:46,
         tilt:100, jitter:16, fold:0, cord:14, shift:1, layer:1, opacity:93, shadow:100, speed:51}
BUNT3 = {seg:[0,0.68], yL:170, yR:-6,  sag:66,  asym:3, step:57, fw:54, fh:47,
         tilt:100, jitter:16, fold:0, cord:16, shift:3, layer:0, opacity:93, shadow:100, speed:100}
```

Две нити идут поверх содержимого, третья за ним. На узком экране третья скрывается, остальные масштабируются: высоты и провис умножаются на 0.62, флажки на 0.78, шаг на 0.74.

Инструмент подбора лежит в `garland-lab.html`. Если понадобится поменять композицию, крутить там, а не в коде.

**Гирлянда: крепление флажков.** Флажок и нить это одно целое: полотнище начинается выше линии на величину подгиба, подгиб рисуется тем же цветом с меньшей непрозрачностью, а нить рисуется поверх флажков. Без подгиба флажок выглядит приклеенным снизу, и это первое, что бросается в глаза как ненастоящее. Концы нити с отрицательной высотой уходят под шапку и перекрываются ею.

Требования из `SPEC.md` раздел 12. Конкретная композиция подбирается визуально и в задании не фиксируется. Гирлянда рендерится в SVG, пересчитывается на изменении размера окна с задержкой 180 мс, проходит за текстом по слою.

**Звёзды.** Мелкие точки со слабым мерцанием во всех секциях главной. Плотность подобрана так, чтобы не мешать чтению. Изредка падающая звезда в первом экране.

**Уменьшенное движение.** При системной настройке `prefers-reduced-motion` все анимации выключаются, содержание остаётся.

## 1.15. Файлы cookie и аналитика

**Что видит гость.** При первом визите баннер внизу с двумя кнопками: принять и только необходимые.

**Логика.**
- Выбор сохраняется, повторно баннер не показывается
- Счётчик статистики подключается только после выбора «принять»
- События аналитики не отправляются до согласия
- Решение можно изменить: ссылка в подвале

**События, которые отправляются.** Открытие страницы занятия, нажатие «Записаться», начало заполнения формы, отправка заявки, отправка заявки на индивидуальное время, нажатие кнопки анкеты.

# ЧАСТЬ 2. ПАНЕЛЬ

Общий контракт всех операций описан в `ARCHITECTURE.md` раздел 7. Ниже логика, специфичная для каждого раздела.

## 2.1. Сегодня

**Что видит администратор.** Расписание на сегодня, список того, что стоит проверить, восемь быстрых действий, поиск.

**Логика блока «что стоит проверить».** Правила, каждое даёт строку при выполнении условия:
- Занятие с готовностью страницы ниже 70 процентов
- Отзыв со статусом «черновик» и неотмеченным согласием
- Неделя без единого занятия в сетке
- Заявка в статусе `failed`
- Категория без единого элемента
- Статья в черновиках дольше 14 дней

**Поиск.** По названиям занятий, работ, товаров, статей, форматов, мастеров. Результат ведёт в нужный раздел панели.

---

## 2.2. Занятия и показатель готовности

**Логика показателя.** Считается по семи признакам, каждый даёт долю:
описание, факты (длительность, уровень, формат), не меньше трёх кадров в галерее, блок «подойдёт если», шаги программы, что входит, привязка работ.

Показатель показывается цветной шкалой и подсказывает, чего не хватает.

**Редактор.** Все поля модели, блоки списками с перетаскиванием, галерея, теги задач анкеты, переключатель показа.

**Крайние случаи.**
- Занятие стоит в расписании и его пытаются удалить: предупреждение со списком слотов
- Смена названия меняет адрес: старый адрес сохраняется для редиректа

---

## 2.2a. Потоки курсов

**Где.** Раздел «Занятия», внутри редактора занятия с форматом «курс».

**Операции.** Добавить поток, изменить, скрыть, удалить. Поля: дата старта, число встреч, текст расписания, примечание.

**Автоматика.** Поток с прошедшей датой старта скрывается фоновой задачей вместе с архивом событий. Не удаляется: остаётся историей.

**Подсказка в разделе «Сегодня».** Если у курса нет ни одного будущего потока, появляется строка «у курса нет открытых наборов».

---

## 2.3. Категории и фильтры

**Логика уровней.** Дерево максимум двух уровней. У первого уровня задаётся тип отображения, второй наследует.

**Операции.** Создать категорию первого уровня, создать подкатегорию с выбором родителя, переименовать, изменить порядок, скрыть, удалить.

**Правила.**
- Удаление категории с элементами запрещено: сначала перенести или удалить элементы
- Скрытие не трогает элементы: они остаются в базе и вернутся вместе с категорией
- Пустая категория не показывается на сайте автоматически, скрывать её вручную не нужно
- Смена типа отображения у первого уровня меняет вид всех подкатегорий

**Где применяется.** Направления и форматы занятий, авторы и материалы работ, категории каталога, подкатегории «Керамистам».

---

## 2.4. Расписание

**Часы работы.** Таблица по дням: открытие, закрытие, выходной. Кнопка «одинаково на всю неделю» копирует первый заполненный день в остальные.

**Сетка недели.** Строки: день, время, занятие. Если время выходит за часы работы, показывается предупреждение, но сохранение разрешено: бывают особые дни.

**Свободное время.** Календарь: отметить день открытым, задать список времени, скопировать набор на другие даты.

**Анкета.** Шесть задач, у каждой название и набор занятий и форматов, которые под неё подбираются.

---

## 2.5. Блог и редактор статей

**Редактор.** Разметка Markdown. Кнопки над полем вставляют разметку в место курсора: заголовок, подзаголовок, жирный, курсив, список, нумерация, цитата, ссылка, изображение, видео.

**Предпросмотр.** Рядом с полем, обновляется на вводе с задержкой. Показывает статью так, как её увидит гость.

**Автосохранение.** Каждые 30 секунд при наличии изменений. Сохраняется черновик, а не публикация. Индикатор показывает время последнего сохранения.

**Закрепление.** Закреплённая статья ровно одна. Закрепление новой снимает прежнюю в той же транзакции.

**Публикация.** Меняет статус на «опубликована», проставляет дату, сбрасывает кэш блога и главной, перестраивает карту сайта.

**Снятие с сайта.** Статус возвращается в черновик, статья исчезает с сайта и из карты сайта, но не удаляется.

**Поля для поиска.** Заголовок и описание. Если пустые, подставляются заголовок статьи и её краткое описание.

**Безопасность.** Markdown очищается от исполняемого кода при сохранении и при выводе. Вставка чужого HTML не выполняется.

---

## 2.6. Отзывы

**Логика согласия.** Поле «согласие получено» обязательно для фото и видео. Попытка публикации без него отклоняется на сервере с понятным объяснением.

**Состояния.** Черновик, опубликован, заблокирован. Заблокированный отзыв это тот, у которого согласие отозвано: он не показывается и не может быть опубликован, пока согласие не отмечено заново.

---

## 2.7. Команда

**Карточка мастера.** Имя, специализация, фраза, опыт.

**Медиа.** Фотографии загружаются, первая становится главной для карточки в карусели. Видео подключается ссылкой.

**Какие занятия ведёт.** Таблица всех занятий с переключателем. Отмеченные появляются на странице мастера с кнопкой записи.

**Важно.** Эта связь только для показа. На запись она не влияет: гость выбирает занятие и время, мастера ставит студия.

---

## 2.8. Медиа

**Загрузка.** Проверка типа по содержимому, ограничение 10 МБ, преобразование в webp, три размера, сохранение по годам и месяцам.

**Таблица файлов.** Имя, где используется, где хранится, вес.

**Удаление.** Только с подтверждением. Если файл используется, показывается список мест.

**Видео.** Только ссылка. Проверяется домен: VK Видео, Rutube, YouTube. Обложка подтягивается с площадки.

**Счётчик места.** Показывает занятый объём и остаток по тарифу.

---

## 2.9. Контент и оформление

**Тексты первого экрана.** Надзаголовок, заголовок, описание, рукописная строка.

**Полоса доверия.** Три факта, каждый с крупной частью и пояснением.

**Порядок блоков главной.** Перетаскивание, переключатель показа у каждого блока. Сохраняется в настройку `blocksOrder`.

**Оформление.** Переключатель трёх режимов. Возможность задать даты, когда зимний режим включается сам.

---

## 2.10. Журнал заявок

**Таблица.** Когда, тип, занятие или повод, контакт, статус отправки в amoCRM.

**Фильтры.** По статусу, показ только незакрытых.

**Операции.** Повторная отправка в amoCRM вручную, выгрузка текстового файла за месяц.

**Шифрование.** В базе имена и телефоны зашифрованы. В панели показываются расшифрованными, в выгрузке тоже.

---

## 2.11. Уведомления Telegram

**Настройки.** Токен бота, идентификатор чата, кнопка тестового уведомления.

**Статус связи.** Показывает время последнего успешного уведомления и последнюю ошибку, если была.

**Ограничение.** Бот односторонний. Вебхуков нет, входящие сообщения не обрабатываются.

---

## 2.12. Настройки и доступы

**Юридические документы.** Политика, согласие на обработку, согласие на публикацию фото и видео. Каждое сохранение создаёт новую версию с датой, старые сохраняются. В заявке фиксируется, какую версию принял гость.

**Сотрудники.** Список, роли, приглашение по одноразовой ссылке, отзыв доступа.

**Только владелец.** Раздел недоступен роли администратора ни через меню, ни прямым обращением.

---

## 2.13. Журнал действий и система

**Журнал действий.** Кто, что, когда, над какой сущностью. Пишется автоматически каждым действием панели.

**Система и безопасность.** Статус последней резервной копии, число заявок в статусе `failed`, последние события безопасности, кнопка завершения всех сессий.

# ЧАСТЬ 3. Сквозные проверки

Выполняются после каждого этапа, а не только в конце.

- [ ] Правка в панели видна на сайте после обновления страницы
- [ ] Скрытие убирает с сайта, но сохраняет запись
- [ ] Изменение порядка меняет порядок на сайте
- [ ] Роль `admin` не может выполнить операцию владельца прямым обращением
- [ ] Все формы проходятся с клавиатуры
- [ ] На ширине 320 нет горизонтальной прокрутки
- [ ] Списки доступны с выключенным JavaScript через адреса страниц
- [ ] Заявка сохраняется, даже если внешние сервисы недоступны
- [ ] Публикация фото и видео гостей невозможна без отметки согласия
- [ ] В консоли браузера нет ошибок
