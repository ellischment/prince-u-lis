### Шаг 1.1 (каталог занятий и страница занятия) — готово

**Осознанное отступление от карты режимов, не забытая правка.** ARCHITECTURE р. 3 относит каталог занятий к статическим страницам с тегами. Выбор сделан в пользу доступности без JavaScript (тоже требование SPEC, часть сквозных проверок) в пользу конкретной этой страницы. База не нагружается лишним: чтения внутри всё равно идут через cachedRead с тегами lessons и categories, тяжёлого прямого обращения к Prisma при каждом заходе нет. Если требование ARCHITECTURE р. 3 по этой странице окажется важнее доступности без JS, чинить нужно сознательно: фильтры на JavaScript плюс отдельный статический список без фильтров для роботов, а не откат к динамике без объяснения. ### Шаг 1.2 (раздел «Занятия» в панели) — готово

Поиск фильтрует в коде, а не через Prisma `contains`: SQLite не поддерживает `mode: "insensitive"` (это только PostgreSQL), а обычный LIKE не сворачивает регистр кириллицы. Важная находка при проверке. lib/action.ts глушил ЛЮБУЮ ошибку из run() одним и тем же общим текстом «Не удалось сохранить», включая специально написанные понятные сообщения (например про занятие в расписании). Администратор никогда не видел, из-за каких именно слотов нельзя удалить. Добавлен класс ActionError: сообщения из него показываются как есть, всё остальное по-прежнему прячется за общий текст и уходит в консоль сервера. Это системное исправление обёртки, действует для всех будущих разделов, не только для занятий.

Открытый пробел, найденный при проверке, не достроен намеренно. Потоки курсов сохраняются и видны в панели, но показать их гостю негде: блок «Ближайшие потоки» по SPEC р. 9a живёт на `/kursy/[slug]`, а этого маршрута не существует вовсе — ни `/kursy`, ни страницы курса.
