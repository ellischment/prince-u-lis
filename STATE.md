### Шаг 0.1 (модель данных и каркас)

- lib/db.ts: клиент Prisma, WAL и busy_timeout при инициализации. Оба PRAGMA вызываются через $queryRawUnsafe: SQLite возвращает строку результата, и $executeRaw на них падает с P2010. Проверено: journal_mode = wal, busy_timeout = 5000
- lib/env.ts: приложение падает при старте со списком незаполненных переменных
- lib/time.ts: московский день недели и дата, считаются явно через Intl (внутри контейнера UTC)
- lib/constants.ts: допустимые значения строковых полей вместо перечислений
- prisma/seed.ts и команда npm run seed. Заполнено: 12 занятий, 4 мастера, 10 работ, 8 товаров, 6 форматов праздников, 4 вида сотрудничества, 3 уровня бонусов, 3 статьи, 4 события, 3 отзыва, 12 слотов расписания, часы работы, открытые дни, тексты главной

### Перенос заготовок (после разбора расхождений)

- SPEC.md и CLAUDE.md заменены на новые версии: в SPEC полная таблица из 19 переменных палитры, в CLAUDE раздел «Единственные источники правды»

- lib/db.ts: заготовка за основу, но $queryRawUnsafe вместо $executeRawUnsafe и без .catch. Промис PRAGMA сохранён в prismaReady, а не потерян через void
- lib/time.ts: оставлена версия на Intl.DateTimeFormat. Заготовочная не взята: toLocaleString зависит от локали процесса, а setHours считает в зоне процесса и на UTC-контейнере даёт сдвиг. Экспорт назван currentWeekdayIndex, как ждут тесты, нумерация 1..7 по schema.prisma и SPEC
- Тесты приведены к 1..7 (понедельник 1, воскресенье 7), лежат в lib/time.test.ts. Добавлен vitest.config.ts, npm run check включает vitest run
- DATABASE_URL переведён на file:./data/dev.db: путь считается от папки prisma, поэтому файл ложится в prisma/data, ровно туда, куда монтируется том db-data. При прежнем file:./dev.db база оказывалась вне тома и стиралась первым же обновлением образа
- Добавлены CRON_SECRET и NEXT_PUBLIC_SITE_URL, без них lib/env.ts роняет старт
- Из Dockerfile и docker-compose.yml убран TZ=Europe/Moscow: контейнер на UTC по ARCHITECTURE р. 2a, московское время считается явно в lib/time.ts

### Шаг 0.3 (вход в панель и роли) — готово

- lib/auth.ts: bcrypt (12 раундов), сессия в httpOnly cookie на 14 дней, sameSite lax, secure в проде. Сессия сверяется в базе при каждом обращении, а не только по подписи: завершение сессий владельцем будет срабатывать сразу
- Хэш сверяется даже когда пользователя нет, иначе по времени ответа перебираются существующие адреса. Сообщение об ошибке общее, существование почты не раскрывает
- Блокировка на час после 5 неудач подряд с одного адреса, попытки пишутся в LoginAttempt
- lib/roles.ts: 17 разделов панели по SPEC р. 13, три из них (настройки, журнал действий, система) только для owner и tech по таблице ARCHITECTURE р. 6
- proxy.ts закрывает всё /admin кроме входа, проверяя наличие куки. Подлинность сессии проверяется в layout панели через currentUser
- app/admin/(panel)/[section]/page.tsx: заглушки всех разделов с серверной проверкой роли. Неизвестный раздел даёт 404
- В seed заведены двое: владелец и администратор, пароли только из переменных окружения, короче десяти символов не принимаются (SPEC р. 16). Существующие записи обновляются, а не пересоздаются, иначе повторный seed рвёт живые сессии

Проверено вручную в браузере, не только сборкой:

- Вход под администратором: 14 разделов в меню, трёх владельческих нет
- Администратор по прямым адресам /admin/settings, /admin/audit, /admin/system получает отказ, а не страницу. Это главная проверка шага
- Вход под владельцем: 17 разделов, /admin/settings открывается
- Неверный пароль: общее сообщение, сессия не создаётся
- Блокировка: после 5 неудач вход отклоняется даже с верным паролем, с указанием срока. Тестовые записи после проверки удалены
- Выход возвращает на страницу входа
- Ширина 320px: горизонтальной прокрутки нет ни в панели, ни на styleguide

Попутно найдено и исправлено: в npm run check команда tsc шла до сборки, а типы маршрутов Next генерирует именно сборка. Из-за этого проверка падала на новой странице, и точно так же упала бы на чистой машине в GitHub Actions, где папки .next нет вообще. Теперь check начинается с next typegen.
