# Отчёт по этапу 0 — Инициализация проекта

## Что сделано

Запущен и настроен весь технический фундамент проекта «Принц и Лис».

### Приложение

- Создан проект Next.js 14 с TypeScript (строгий режим), Tailwind CSS и App Router
- Настроены шрифты Forum и Manrope через Google Fonts
- Прописаны все цвета, тени и радиусы из дизайна (тёмная тема сайта + светлая тема админки)
- Готовы анимации: мерцание звёзд, движения лиса, скролл-ревил

### База данных

- Схема Prisma с 11 моделями: категории, услуги, слоты, записи, акции, промокоды, пользователи, контент, журнал
- Docker Compose поднимает PostgreSQL 16 локально одной командой
- Seed-файл: пользователь Лизы, демо-услуги (7 позиций), расписание, акции, промокод LISA10

### Авторизация

- NextAuth с логином по email + паролю (bcrypt)
- JWT-сессия, роли OWNER и ADMIN
- Middleware блокирует `/admin/*` без сессии, скрывает «Настройки» и «Журнал» от ADMIN

### Инфраструктура

- ESLint + Prettier настроены, lint проходит без замечаний
- Vitest + Testing Library — 4 теста проходят
- Husky: pre-commit запускает lint-staged (ESLint + Prettier на изменённых файлах)
- `.gitignore` исключает `.env`, `node_modules`, `.next`
- `.env.example` с описанием всех переменных

## Что отложено

- Docker нужно запустить вручную (`docker compose up -d`) перед работой с базой
- Seed запускается отдельно (`npm run db:seed`) после миграции
- Реальные страницы сайта и админки — этап 1
- Оплата, email, Telegram-бот, фото — более поздние этапы

## Принятые решения

- Vitest вместо Jest: быстрее, лучше дружит с ESM и Next.js
- `vitest.config.ts` исключён из основного `tsconfig.json` — иначе Next.js ругается на конфликт типов Vite
- В `auth.ts` кастинг через `unknown` для поля `role` — стандартный обход ограничения типов NextAuth v4
- Seed удаляет и пересоздаёт расписание каждый раз (простота важнее оптимизации на старте)
- Все тексты интерфейса на русском языке
