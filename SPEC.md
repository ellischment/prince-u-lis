| Стили | CSS-модули или Tailwind, без UI-китов |

| Хостинг | VPS в России, Docker Compose, Caddy для HTTPS |

Внутреннее устройство, кэш, серверные действия, конвейер заявки и фоновые задачи описаны в `ARCHITECTURE.md`.

## 2. Модель данных

Все таблицы имеют `id`, `createdAt`, `updatedAt`. Поле `visible` (bool) означает показ на сайте. Поле `sort` (int) задаёт порядок.

### Category
Категории каталогов и фильтров. Самоссылающееся дерево максимум двух уровней.
```
id, title, slug, parentId (null для первого уровня), kind, display, visible, sort
```
- `kind`: `lesson_direction` | `lesson_format` | `work_author` | `work_material` | `shop`
- `display` (только для первого уровня, второй наследует): `showcase` (сетка фото без подписей) | `cards` (фото, название, цена, переход)

### Lesson (занятие)
```
id, title, slug, directionId, formatId, price, duration, level, format,
intro, notForBeginnersText, note, visible, sort, readiness (0..100)
LessonFit[]      // «подойдёт, если», строки
LessonStep[]     // «как проходит», шаги по порядку
LessonInclude[]  // «что входит»
LessonTaskTag[]  // теги задач анкеты
Media[]          // галерея
```

### CourseRun (поток курса)
Курс это занятие с форматом `course`. Поток это конкретный запуск с датой старта.
```
id, lessonId, startDate, sessionsCount, timeText, note, visible, sort
```
- `startDate`: дата первого занятия потока
- `sessionsCount`: сколько встреч в потоке
- `timeText`: когда проходят встречи, например «по субботам в 12:00»
- Поток с прошедшей датой старта автоматически скрывается с сайта

### Master (мастер)
```
id, name, slug, speciality, quote, experience, visible, sort
Media[]          // фото и видео
LessonsTaught[]  // связь многие-ко-многим с Lesson
```

### Work (работа)
```
id, title, slug, authorId (категория «Елисаветы» | «мастеров»), materialId, price, description, short, visible, sort
Media[]
```

### ShopItem (товар-услуга)
```
id, title, slug, categoryId (kind=shop), price, description, terms, visible, sort
Media[]
```

### Celebration (формат праздника)
```
id, title, slug, intro, priceHint, visible, sort
CelebrationStep[]     // как проходит
CelebrationInclude[]  // что входит
Media[]               // до 5, включая видео
```

### Partnership (вид сотрудничества)
```
id, title, slug, description, visible, sort
PartnershipStep[]   // как проходит
PartnershipNeed[]   // что написать в заявке
```

### BonusLevel (уровень бонусов)
```
id, title, levelLabel, condition, accent, visible, sort
BonusPerk[]
```

### Article (статья)
```
id, title, slug, excerpt, bodyMarkdown, coverId, topic, lessonId (nullable),
pinned (bool, ровно одна true), status (draft|published), publishedAt,
seoTitle, seoDescription
```

### Event (событие)
```
id, title, slug, date, description, visible
Media[]
```

### Review (отзыв)
```
id, guestName, kind (text|photo|video), text, videoUrl, mediaId,
consentReceived (bool), status (draft|published|blocked)
```
Правило: `status=published` невозможен при `kind in (photo,video)` и `consentReceived=false`.

### ScheduleSlot (сетка недели)
```
id, weekday (1..7), time, lessonId, visible, sort
```

### FreeDay (открытые дни индивидуальных заявок)
```
id, date, times (json массив строк), visible
```

### StudioHours
```
id, weekday (1..7), opensAt, closesAt, dayOff (bool)
```

### Request (заявка)
```
id, type, lessonId, dateText, timeText, name, phone, channel, comment,
consentVersion, consentAt, ip, amoDealId (nullable), amoStatus (pending|sent|failed),
attempts, createdAt
```
`type`: `booking` | `free_time` | `celebration` | `purchase` | `partnership`

### SiteText (тексты и настройки)
```
key, value (json)
```
Ключи: `hero.title`, `hero.subtitle`, `hero.hand`, `trust.items`, `season`, `blocksOrder`, `partnership.replyTime`, `faq.items`

### User (доступ в панель)
```
id, email, passwordHash, role (admin|owner|tech), active
```

### AuditLog
```
id, userId, action, entity, entityId, payload, createdAt
```

### Media
```
id, kind (image|video), path (для image), url (для video), alt, width, height, bytes, sort
```

## 5. Главная

Порядок блоков задаётся `blocksOrder`, любой блок скрывается.

1. Первый экран: надзаголовок, H1, описание, две кнопки, рукописная строка, иллюстрация в круглом медальоне.
2. Полоса доверия: три факта из `trust.items`.
3. Анкета «Чем займёмся»: шесть кнопок по поводу. Подбор по тегам задач.
4. Каталог занятий: два ряда фильтров (направление, формат), карточки, ссылка на все занятия.
5. Расписание: два столбца.
6. Команда: карусель со стрелками, стрелки видны только при переполнении.
7. Работы: полоса, поддерживает фото, видео и короткое описание.
8. События: два ближайших будущих и одно последнее прошедшее.
9. Блог: три статьи, закреплённая первой.
10. Отзывы: три штуки.
11. Запись: форма в три шага.
12. Контакты: адрес, часы, телефон, мессенджеры. Карты нет.

### Анкета: соответствие задач
| Кнопка | tag | Подбор |
|---|---|---|
| Иду вдвоём | duo | парные занятия + формат «Свидание» |
| Иду с ребёнком | kids | детские и семейные + «День рождения» |
| Ищу подарок | gift | сертификат + подходящие занятия |

Нажатие меняет заголовок каталога на «Вот что вам подойдёт» и показывает кнопку сброса. Повторное нажатие снимает выбор.

## 6. Страница занятия

Блоки сверху вниз: заголовок (направление, H1, описание), факты (длительность, уровень, формат), галерея (одно крупное и мелкие, просмотр на весь экран с листанием стрелками, клавишами и миниатюрами, закрытие по Esc, видео там же), закреплённый блок цены с кнопкой записи, «Подойдёт, если», «Не умеете рисовать», «Как проходит» по шагам, «Что входит», работы гостей, похожие занятия, повтор цены.

Не указываются: имена преподавателей, количество мест.
На узком экране при прокрутке снизу появляется закреплённая полоса с ценой и кнопкой.

## 7. Расписание

### Левый столбец
Семь дней недели без чисел, всегда с понедельника. Развёрнут день недели, соответствующий текущему дню на сервере. Рядом ключевые слова, собранные из направлений занятий дня. Внутри: название занятия ссылкой на страницу, время, кнопка записи. Пустой день показывает предложение прийти индивидуально. Отдельный блок с ближайшим курсом.

### Правый столбец
Заголовок «Не нашли своё время?». Календарь месяца, открытые дни подсвечены, под ним легенда. После выбора дня список конкретного времени плюс кнопка «любое время» плюс поле «нужно другое время». Под кнопкой обязательная фраза: это заявка, а не бронь, время не помечается занятым. После отправки подтверждение на месте.

## 8. Онлайн-запись

Три шага: выбор занятия из списка (сгруппирован по направлениям, с ценой, есть пункт «пока выбираю»), имя и телефон (обязательные), канал связи (звонок по умолчанию) и комментарий.

Под списком сводка выбранного: длительность, уровень, цена, время если пришли из расписания. Из сводки переход на страницу занятия и сброс выбора.

Галочка согласия обязательна, заранее не отмечена, со ссылкой на политику. Сохраняется версия документа, дата, IP.

Валидация: пустые обязательные поля подсвечиваются, курсор в первое, форма не очищается. После успеха форма заменяется экраном подтверждения с названием занятия и кнопкой отправить ещё одну.

Регистрации нет. Количество мест не показывается и не хранится.

## 9. Каталог «Купить»

Три вкладки: Работы, Сертификаты и курсы, Керамистам.

- Работы: сетка фото без подписей, порциями с кнопкой «показать ещё». Два уровня фильтра: автор (все, Елисаветы, мастеров) и материал (керамика, живопись, витраж). Работают вместе, пустое сочетание даёт подсказку.
- Сертификаты и курсы: карточки с описанием и переходом. Здесь же коворкинг, к нему ведёт пункт меню.
- Керамистам: карточки как у сертификатов. Подкатегории второго уровня: глина и массы, глазури и ангобы, инструмент, обжиг.

Категории создаются в панели: название, уровень, тип отображения, показ, порядок. Пустая категория не показывается.

**Фильтры настраиваются в панели на каждом уровне.** Это относится ко всем рядам фильтров: направления и форматы занятий, авторы и материалы работ, подкатегории «Керамистам», задачи анкеты. Добавление, переименование, порядок и скрытие без участия разработчика. Скрытие не удаляет привязанные сущности.

## 9a. Курсы

Отдельный раздел, потому что курс это другой тип решения: человек платит вперёд за несколько встреч, а не за один визит. Средний чек курса выше разового занятия в три-четыре раза.

- `/kursy`: витрина курсов карточками. У каждой название, число встреч, цена за курс, ближайшая дата старта
- `/kursy/[slug]`: страница курса. Состав как у страницы занятия, плюс блок «Ближайшие потоки»: дата старта, число встреч, когда проходят, кнопка записи с подставленным потоком
- Курс это занятие с форматом `course`. Отдельной сущности нет, чтобы не дублировать содержимое
- В каталоге занятий курсы продолжают показываться по фильтру формата
- Если открытых потоков нет, показывается кнопка «Сообщить о наборе» с заявкой типа `booking` и пометкой в комментарии
- Заявка на курс уходит с указанием потока и даты старта

## 10. Остальные разделы

- **Отпраздновать**: сетка форматов, страница формата (описание, шаги, что входит, ориентир цены, форма), карусель до пяти фото и видео.
- **Сотрудничество**: четыре вида, карточка каждого (шаги, что написать в заявке), форма с выбранным видом, тег в CRM.
- **Бонусы**: паспорта по уровням, визуально разделённые гранью, оттенком и номером.
- **Блог**: список порциями, закреплённая первой, статья из Markdown.

### Индексация статей
Обязательное требование, влияет на реализацию списка.
- Страница статьи рендерится на сервере, робот получает готовый HTML
- Пагинация имеет реальные адреса `/blog`, `/blog/2` и далее. Кнопка «показать ещё» дополняет их, но не заменяет
- Все опубликованные статьи в `sitemap.xml`, обновляется при публикации
- Свои `title` и `description`, при пустых полях подставляются заголовок и excerpt
- Ровно один H1, дальше H2 и H3 из Markdown
- Разметка Article: заголовок, описание, обложка, дата, автор
- Черновики и снятые статьи имеют `noindex` и не попадают в sitemap
- Смена slug даёт редирект 301 со старого адреса
- То же правило для работ и событий: свой адрес у каждой карточки, наличие в sitemap
- **Отзывы**: три формата, видео ссылкой, обязательная отметка согласия.
- **События**: карусель, после даты уходит в прошедшие.

Шрифты: Cormorant Garamond (заголовки), Manrope (текст), Neucha (рукописные акценты).

Гирлянда: нить провисает по катенаре, крепления на видимых точках или под шапкой, флажки нанизаны на нить с подгибом ткани через ленту, нить проходит поверх подгиба. Наклон флажков следует за нитью с доворотом к вертикали, качание волной, амплитуда больше в провисе. Не привязана к курсору, прокручивается со страницей.

У каждой нити настраивается слой: за содержимым или поверх него. Нить поверх заходит на заголовок и иллюстрацию, при этом обязательна тень флажков и проверка читаемости текста под ними. Кнопки и ссылки гирляндой не перекрываются.

Конкретная композиция подбирается визуально и в задании не фиксируется.

Три режима: флажки, зима со снегом, без оформления.

Движение: редкая падающая звезда, дыхание медальона, плавное появление секций, подсветка текущего раздела, кнопка наверх. Всё выключается при `prefers-reduced-motion`.

Запрещено: эффекты за курсором, автозапуск видео со звуком, всплывающие окна на первом экране.

## 13. Панель управления

Роли: `admin` (содержимое и расписание), `owner` (всё), `tech` (как owner).

Разделы: Сегодня, Расписание, Занятия, Купить, Отпраздновать, Команда мастеров, Отзывы, Блог, События, Бонусы, Фото и видео, Контент и оформление, Уведомления Telegram, Журнал заявок, Настройки и доступы, Журнал действий, Система и безопасность.

Правила: без смайликов, состояния словами и цветом, опасные действия с подтверждением, названия разделов совпадают с сайтом, поиск по содержимому, быстрые действия на главном экране.

Чего в панели нет: списка клиентов, подтверждения и отмены записи, подсчёта мест, календаря занятости мастеров.

Редактор статей: Markdown, кнопки разметки, живой предпросмотр, поля для поиска, автосохранение черновика раз в 30 секунд, предпросмотр глазами гостя, снятие с сайта без удаления.

Фото и видео: изображения загружаются и лежат на сервере, сжимаются sharp, создаются версии под телефон. Видео только ссылкой на VK Видео, Rutube, YouTube.

## 14. Интеграция с amoCRM

amoCRM главная система. Сайт создаёт сделку и не читает клиентов обратно.

Поля сделки: занятие, дата и время, имя, телефон, канал связи, комментарий, источник. Тег по типу заявки.

Порядок обработки заявки:
1. Валидация на сервере.
2. Запись в таблицу `Request` со статусом `pending`.
3. Запись строки в текстовый журнал месяца.
4. Отправка в amoCRM. Успех: `sent` + `amoDealId`. Ошибка: `failed`, повтор по расписанию с задержками 1, 5, 15, 60 минут, максимум 5 попыток.
5. Отправка уведомления в Telegram со ссылкой на сделку.

Дедупликация: одинаковые телефон и тип заявки в течение 10 минут не создают новую сделку.

Токены amoCRM хранятся в переменных окружения, обновляются по refresh-токену.

## 15. Уведомления в Telegram

Одностороннее. Бот только отправляет, вебхуков и обработки ответов нет.

Состав сообщения: тип заявки, занятие или повод, имя, телефон, канал связи, комментарий, ссылка на сделку.

Что бот не делает: не подтверждает и не отменяет, не переносит, не пишет клиентам, не принимает команды, не считает места.

Настройка: токен BotFather и chat_id в переменных окружения и в панели, кнопка тестового уведомления.

## 16. Безопасность и закон

- Сервер и резервные копии в России.
- Телефоны и имена шифруются в базе (AES-GCM, ключ в переменных окружения).
- Ежедневная резервная копия в 04:00, хранение 30 последних, ежемесячная проверка восстановления.
- Ограничение частоты запросов к формам: не более 5 заявок с одного IP за 10 минут.
- Проверка загружаемых файлов по содержимому, а не по расширению.
- Заголовки безопасности: CSP, HSTS, X-Content-Type-Options, Referrer-Policy.
- Пароли: bcrypt, минимум 10 символов, блокировка на час после 5 неудач.
- Сессии: httpOnly, secure, sameSite=lax, срок 14 дней.
- Оператор персональных данных студия. Тексты политики и согласий предоставляет студия. Версия согласия сохраняется с заявкой.
- Cookie-баннер: аналитика подключается только после согласия.
- Фото и видео гостей публикуются только при `consentReceived=true`.

## 17. Доступность и скорость

- Управление с клавиатуры для всех действий, включая выбор занятия.
- Видимый фокус, контраст AA, alt у изображений, aria-label у кнопок.
- Ширина от 320px без горизонтальной прокрутки.
- LCP до 2,5 секунды на среднем телефоне, INP до 200 мс, CLS до 0,1.
- Изображения в webp, ленивая загрузка, шрифты с `display: swap`.

## 18. Аналитика

События: `lesson_view`, `booking_click`, `booking_start`, `booking_submit`, `freetime_submit`, `quiz_click`. Отправляются только после согласия на аналитические cookie. Доступ к статистике передаётся студии.

## 19. Что не входит

Оплата на сайте, личный кабинет гостя, мобильное приложение, поисковое продвижение, написание текстов, фотосъёмка, автоматические напоминания клиентам, перенос базы из amoCRM.
